# 能力雷达图计算方式

## 1. 目标与边界

能力雷达图用于对比“岗位要求强度”和“简历证据体现的能力强度”，固定包含六个维度：

1. 技能：工具、语言、算法、技术栈等。
2. 经验：学习、参与、负责、主导等经历深度。
3. 项目：项目参与程度、责任范围、完成与交付情况。
4. 成果：论文、专利、作品、证书及可验证产出。
5. 教育专业：学历层级、专业方向及与岗位的相关性。
6. 行业领域：行业背景、业务场景和领域知识。

雷达图不替代“硬性条件检查”。年龄、地点、最低年限、必须持有的证书等硬性条件继续单独核查，不混入六维能力分。

## 2. 计算职责

- AI 只负责从 JD 和简历中提取结构化要求、证据及离散等级，不直接决定最终分数。
- 确定性算法把 AI 输出的离散等级映射为分数，并完成聚合、权重归一化和状态判断。
- 前端只消费算法结果并展示，不在浏览器内重新推导业务分数。

这样可以保证同一份结构化输入始终得到同一结果，并能追溯每个分数对应的岗位原文和简历原文。

## 3. AI 需要输出的单项结构

每一条非硬性岗位要求都归入一个维度，并提供：

- `requirement`：标准化后的要求项名称。
- `dimension`：六个固定维度之一。
- `importance`：`core`、`important`、`normal`、`bonus`。
- `requiredDepth`：`basic`、`familiar`、`practical`、`expert`。
- `jobEvidence`：岗位原文摘录。
- `resumeEvidenceLevel`：`none`、`mentioned`、`used`、`owned`、`achieved`。
- `relevance`：`none`、`weak`、`partial`、`high`、`exact`。
- `resumeEvidence`：简历原文摘录；未发现时为空。

AI 只能根据原文选择等级。没有原文证据时必须使用 `none`，不能推测候选人具备相关能力。

## 4. 固定映射表

### 4.1 岗位要求重要度

| 等级 | 系数 |
| --- | ---: |
| `core` 核心/必须 | 1.0 |
| `important` 明确要求 | 0.8 |
| `normal` 一般要求 | 0.5 |
| `bonus` 优先/加分项 | 0.3 |

### 4.2 岗位要求深度

| 等级 | 分数 |
| --- | ---: |
| `basic` 了解基础概念 | 40 |
| `familiar` 熟悉并可使用 | 60 |
| `practical` 有独立实践 | 80 |
| `expert` 精通、主导复杂任务 | 100 |

### 4.3 简历证据等级

| 等级 | 分数 |
| --- | ---: |
| `none` 未发现证据 | 0 |
| `mentioned` 仅提及或只在列表出现 | 30 |
| `used` 在学习、工作或项目中使用 | 60 |
| `owned` 独立负责或承担关键职责 | 80 |
| `achieved` 有量化成果、复杂实践或可验证产出 | 100 |

### 4.4 证据相关度

| 等级 | 系数 |
| --- | ---: |
| `none` 无关 | 0 |
| `weak` 弱相关 | 0.2 |
| `partial` 部分相关 | 0.5 |
| `high` 高度相关 | 0.8 |
| `exact` 完全对应 | 1.0 |

## 5. 计算公式

### 5.1 单项分数

```text
单项岗位要求分 = 岗位要求深度分
单项简历能力分 = 简历证据分 × 证据相关度
```

重要度不在单项分数中重复相乘，而是在维度聚合和维度权重中使用。

### 5.2 维度分数

对某一维度下的全部要求项进行重要度加权：

```text
维度岗位要求分 = Σ(单项岗位要求分 × 单项重要度) ÷ Σ(单项重要度)
维度简历能力分 = Σ(单项简历能力分 × 单项重要度) ÷ Σ(单项重要度)
```

两项结果四舍五入为 `0—100` 的整数。

如果岗位没有该维度的要求：

- 该维度 `weight = 0`，不参与综合匹配分。
- 雷达图岗位要求分和简历能力分均为 `0`。
- 状态显示“岗位未要求”，不标为优势或缺口。第一版只处理岗位要求对应的简历证据，不额外扫描和展示岗位未要求的简历能力。

### 5.3 维度匹配度

```text
维度匹配度 = min(维度简历能力分 ÷ 维度岗位要求分, 1) × 100
```

岗位要求分为 `0` 时，维度匹配度记为 `null`，不参与综合分。候选人能力超过岗位要求时匹配度封顶 `100`，不能抵消其他维度的缺口。

### 5.4 维度权重

先计算每个维度的要求重要性：

```text
维度重要性 = Σ(该维度内要求项重要度)
原始权重 = 维度重要性 ÷ 全部维度重要性之和
```

约束规则：

1. 计算层按结构化要求项逐项计算，不自行判断或合并同义项；同义要求的归并由 AI 生成结构化要求时完成。
2. 有明确要求的维度权重最低为 5%。
3. 单个维度权重最高为 40%。
4. 经过上下限调整后再次归一化，确保所有参与计算的维度权重合计为 100%。
5. 没有岗位要求的维度权重为 0%。

### 5.5 综合能力匹配分

```text
综合能力匹配分 = Σ(维度匹配度 × 维度权重)
```

该分数只表达六维能力覆盖程度。硬性条件是否影响页面顶部的“综合分”，由现有综合评分规则单独处理，并必须明确展示调整原因，不能暗中扣分。

## 6. 状态判断

维度状态使用以下规则：

- `matched` 已匹配：维度匹配度不低于 80%，且没有核心要求处于“未发现”。
- `missing` 未发现：维度简历能力分为 0，或该维度“未发现”要求项占比不低于 60%。
- `partial` 部分匹配：有简历能力证据，但不满足 `matched` 或 `missing` 条件。
- `not_required` 岗位未要求：该维度没有结构化岗位要求。

“未发现”只表示当前简历没有可验证证据，不等于候选人不会或不具备该能力。

## 7. 优势与差距排序

```text
优势贡献 = 维度匹配度 × 维度权重
差距影响 = (100 - 维度匹配度) × 维度权重
```

- 主要优势：按优势贡献降序取前 2 项，并要求维度匹配度不低于 80%。
- 关键差距：按差距影响降序取前 2 项，并排除岗位未要求的维度。
- 第一版不额外引入证据可信度系数；证据等级和相关度已经体现在维度简历能力分中。

## 8. 前端结果结构

后端返回给前端的 `capabilityRadar`：

```json
{
  "scoringVersion": "radar-v1",
  "dimensions": [
    {
      "key": "skill",
      "label": "技能",
      "jobScore": 88,
      "resumeScore": 72,
      "matchScore": 82,
      "weight": 32,
      "status": "matched",
      "matchedCount": 4,
      "partialCount": 1,
      "missingCount": 1
    }
  ],
  "advantages": ["项目", "成果"],
  "keyGaps": ["技能", "行业领域"]
}
```

`dimensions` 必须固定按“技能、经验、项目、成果、教育专业、行业领域”排序，便于不同岗位间保持稳定阅读位置。

## 9. 前端展示内容

能力雷达图卡片放在“综合总结”之后、“硬性条件检查”之前，包含：

1. 双轮廓雷达图：简历能力为实线填充，岗位要求为虚线。
2. 明确图例：不只依赖颜色区分。
3. 六维列表：维度名称、简历分、岗位要求分、匹配状态和权重。
4. 摘要：最多两个主要优势、最多两个关键差距。
5. 说明：“未发现”表示简历中暂无明确证据。
6. 历史记录没有 `capabilityRadar` 时展示空状态，提示重新分析；禁止根据旧总分随机生成六维分数。

## 10. 人工修正后的重算原则

人工修正应修改底层要求项或证据等级，不允许直接拖动雷达图节点修改分数。保存修正后，从单项分数开始重新计算维度分、权重、综合能力匹配分、优势和差距，并记录：

- 原识别等级。
- 修正后等级。
- 修正依据。
- 修正时间。
- 是否由人工校准。
